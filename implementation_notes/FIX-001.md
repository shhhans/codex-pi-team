## Scope delivered

Per Lead assignment, the Executive produced the minimal test-side fix for the
empty Terminal popups reported by the Pi Team test suite. The fix:

1. Replaces the unconditional `-WindowStyle Normal` in
   `scripts/pi-team.ps1 Start-RoleProcess` with a conditional driven by the
   opt-in env var `PI_TEAM_TEST_NO_WINDOW`. The default branch (no env var, or
   any value other than `'1'`) keeps `-WindowStyle Normal` so production
   `wt.exe` role terminals remain user-visible. The test branch sets
   `PI_TEAM_TEST_NO_WINDOW=1` and switches to `-WindowStyle Hidden` so the
   `.cmd` and `.ps1` fake launchers do not flash empty console windows during
   `tests/run-tests.ps1`.
2. Sets `PI_TEAM_TEST_NO_WINDOW=1` in the `run(...)` helper of
   `tests/team-contract.test.mjs`. The env var propagates through
   `Start-Process` (which inherits the parent's process env vars by default)
   and reaches the launcher invocation.
3. Adds a bounded retry-loop regression assertion in the same test's `finally`
   block that verifies every recorded launcher / runtime PID captured in the
   state file has exited after the standard 750 ms `Start-Process` cleanup
   wait. The retry loop tolerates the variable Windows process teardown
   latency observed on busy machines.

No production code path was widened. The conditional is opt-in, the default
matches the pre-fix behavior bit-for-bit, and the only test that consumes the
new env var is the existing fake-launcher test. PERF-005's Wait-RoleReady
and bootstrap encoding paths are untouched.

### scripts/pi-team.ps1 (`Start-RoleProcess`)

The unconditional `-WindowStyle Normal` becomes:

```powershell
# Real wt.exe launches remain visible by design. The PI_TEAM_TEST_NO_WINDOW=1
# escape hatch is opt-in for tests/run-tests.ps1 and its fake launchers
# (.cmd/.ps1 wrappers) so the test suite no longer pops up empty console
# windows. The default (no env var, or any value other than '1') keeps
# -WindowStyle Normal so production role Terminals stay user-visible.
$windowStyle = if ($env:PI_TEAM_TEST_NO_WINDOW -eq '1') { 'Hidden' } else { 'Normal' }
return Start-Process $Executable -WorkingDirectory $WorkingDirectory -ArgumentList $commandLine -WindowStyle $windowStyle -PassThru
```

The function's parameter list, return value (`Process` object passed
through to `Launch-Role` for the `launcher_pid` capture), `try/finally`
identity-restore contract, and the rest of `Start-RoleProcess` are unchanged.
No new dependency, no signature change, no env-var side effect on
production invocation (the production code path never sets the env var).

### tests/team-contract.test.mjs (`role launchers inject common-dir identity`)

1. The `run(...)` helper now merges a `baseTestEnv = { PI_TEAM_TEST_NO_WINDOW: "1" }`
   into the spawned `pi-team.ps1` environment. `extraEnv` continues to take
   precedence so individual invocations can still override (kept for
   flexibility; no test currently overrides it).
2. The `finally` block of the launcher test records every `launcher_pid` /

The existing assertions on start / research / resume / session IDs / agent IDs
/ tool lists / state-file structure / runtime-file paths / environment
isolation are untouched. The added assertion layer (PID aliveness) is

## Behavioral contract assertions

The single `Start-RoleProcess` change is bounded as follows:

1. `$env:PI_TEAM_TEST_NO_WINDOW` unset or `!= '1'` → `WindowStyle = 'Normal'`
   (pre-fix behavior).
2. `$env:PI_TEAM_TEST_NO_WINDOW = '1'` → `WindowStyle = 'Hidden'`.
3. The return value is still the `Start-Process -PassThru` `System.Diagnostics.Process`
   object so `Launch-Role` continues to capture `$proc.Id` as
   `State.sessions.$Role.launcher_pid`.
4. The `try/finally` env-var restore is unchanged, so the env var is
   never leaked to the rest of the `pi-team.ps1` caller.
5. `Stop-RoleTree` continues to use `taskkill.exe /PID /T /F` for graceful
   cleanup; the new window-style conditional is compatible with that path.

The only test that exercises the new branch is the existing fake-launcher
test. The other tests in `tests/team-contract.test.mjs` (v2 contracts,
acceptance, role event storage) do not invoke `Start-RoleProcess`; they
continue to pass without modification.

## Remaining risks (待测)

- Hidden window style for `Start-Process -WindowStyle Hidden` is documented
  PowerShell behavior (Windows `CreateProcess` STARTUPINFO `wShowWindow =
  SW_HIDE`). It was not directly captured via Win32 `EnumWindows` in this
  slice because the test path is concurrent with the host's other Pi
  activity, which makes window enumeration unreliable. The diff and the
  conditional comment are the static evidence; the deterministic PID-cleanup
  assertion is the dynamic evidence.
- The 750 ms `Start-Process` cleanup wait is OS-load-dependent. The retry
  loop absorbs the typical 250–1 250 ms variance observed during
  reproducibility runs (10/10 pass with this loop). If a future machine is
  substantially slower, the loop's 20 × 250 ms upper bound may need to grow.
  This is recorded as a machine-load-bound assumption, not a defect.
