---
name: coordinate-group
description: Coordinate a persistent module group through file-based planning, one adversarial review, implementation and code review.
---
Read the current task and work with team_read. Only Lead changes the durable groups/<id>/group.md definition. Maintain task.md and submit it to hand off to Executor. Same-group peers fix and review directly. Resolve blockers in decision-<round>.md (kind resolution), never alter prior evidence. After a passing code review, independently check Validator's assigned module-documentation alignment: inspect the registered code commit, documentation commit, each documentation_checklist item, and the actual module text. Submit documentation_review with pass or changes_requested and explain the evidence. Submit delivery.md to Lead only after both code and documentation reviews pass. Only Lead accepts and integrates. Cross-group communication is Coordinator-to-Coordinator; report changed external commitments to Lead. All process paths are groups/<group>/tasks/<task>/. Each artifact has one author and is submitted once; implementation.md has versioned snapshots. Use team_send for questions/replies, never as a replacement for team_submit. Use team_service only for structured lifecycle actions on named services declared in the target project's .pi/services.json; inspect before start/stop and use review mode for a registered delivery snapshot. Save a concise current-task summary before compact when asked. Keep the group available and end completed turns idle.

Task identity is injected by runtime. Use the owned work_id; round and review target can derive from that work. Require an ok:true submission receipt. On rejection follow code/next_action and authoritative work; never infer success from prose. Handle incoming steering messages before delivery. Preserve frozen delivery files; independent review evidence goes under review-NN/. An unfinished_work alert requires Coordinator recovery or escalation. Group onboarding is finite and separate from business tasks; the definition is Lead-owned, and Coordinator acknowledges the assigned responsibilities only after receiving both Executor and Validator acknowledgements.
